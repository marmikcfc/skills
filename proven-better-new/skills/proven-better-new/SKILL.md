# Proven · Better · New (PBN) Analysis

Pressure-test a product idea using Mark Pincus's PBN framework (developed at
Zynga). Premise: human *instincts* are right ~95% of the time, but specific
*ideas* are wrong ~75% of the time. So the job is to **isolate the
innovation zone** — nail the Proven foundation and obviously-Better polish
so the product cannot die for the *wrong reason*, leaving only the risky
*New* bet exposed to the market as fast as possible.

The full source material lives in `references/framework.md`. Read it if you
need exact wording or the adjacent operating principles (founder mode,
MVP trap, "heat"); the working method below is derived from it.

## Core principles to hold throughout

- **Proven ≠ what's hot right now.** What's trending is usually *New* (high
  failure rate). Proven = mechanics that have crossed time and are
  validated on **retention AND monetization** for a *specific audience on a
  specific platform*.
- **Proven is always relative to an audience + platform**, never abstract.
  "Feed" is proven — but proven *for whom, where?* If the idea has no named
  audience yet, say so and either ask for one or state the analysis is
  market-level (not yet actionable).
- **Distribution is part of Proven.** A channel that isn't proven for this
  specific audience is a "wrong reason" failure risk, same as a bad FTUE —
  don't let it slide through unexamined because it's not a "product"
  feature.
- **Watch for the MVP trap.** If the founder (or you) is already emotionally
  attached to the New bet before it's been tested, say so explicitly — the
  fix is a faster/cheaper test, not more building.
- Be a critical thinker, not a cheerleader. The most valuable outputs are:
  (a) which "Proven" table stakes the founder hasn't earned the right to
  skip, and (b) an honest call on whether the "New" bet is real innovation
  or just disguised risk.

## How to run the analysis

### Step 0 — Frame the idea
Restate the idea in one line, and name the **target audience + platform**.
If missing, flag it — the Proven layer is meaningless without it.

### Step 1 — PROVEN (earn the right to innovate)
Identify the "best of breed" elements already working for this
audience/platform that the product must copy near-perfectly. Two layers:
- **Proven business model** — subscription / vertical SaaS / marketplace /
  transactional / ad-supported. Which one is validated for this audience,
  and is it realistic for the team to run?
- **Proven product mechanics** — the table-stakes UX that kills products
  when done badly: FTUE/onboarding, the core loop borrowed from the
  category leader (Scrabble → Words with Friends), sign-up, payment, the
  dominant interaction pattern (feed / swipe / streak / search).
- **Proven distribution** — is the acquisition channel itself proven for
  this audience, or is the founder assuming it'll "figure itself out" post-launch?

**Ground this step in evidence.** Use WebSearch to pull real proof points —
Day-1/7/30 retention benchmarks by category, ARPU/subscription-revenue
data, market size, the category leader's numbers. Cite sources. Distinguish
"market-level proven" from "proven *for this specific audience*."

Then state the **"wrong reason" failure risk**: the specific Proven element
that, if skipped or done amateurishly, would kill the product regardless of
how good the New idea is. (Even legendary designers fail if they ignore
proven onboarding.)

### Step 2 — BETTER (obviously superior, 10/10 agree)
List incremental improvements so clearly better that **10 out of 10
existing users** of the incumbent would agree. Test each candidate:
- Is it **statistically provable** (faster, cheaper, higher completion), not
  a matter of taste?
- Classic Betters: make it free, remove the download/install, more speed,
  more polish, less friction.
- **Consensus gate:** if only *some* users would prefer it, it is NOT
  Better — it's actually New. Move it to Step 3 and label the
  reclassification.

### Step 3 — NEW (the back-of-the-box reason to try)
Name the single novel bet — the reason a consumer tries this in the first
place (Words with Friends' New = the Facebook social graph). Then:
- **Assume the first New is wrong** (highest-failure component). State how
  you'd get market signal on it fastest and cheapest — this is the MVP-trap
  check: is the test actually cheap, or is it a full build in disguise?
- **Require 2–4 backup New bets** ready to test once Proven + Better are
  solid. A PBN analysis without backup bets is incomplete.
- **Name what "heat" would look like** if this bet is working — the
  observable signal (retention, word of mouth, engagement) that would tell
  you to double down rather than swap in a backup bet.
- Judge honestly: is this real innovation, or a "Better" that failed the
  consensus gate, or just risk with no upside?

## Required output shape

Produce, in this order:

1. **One-line verdict** — is the idea PBN-sound? Plus the single most
   important insight.
2. **Idea + audience/platform** — the framing, with a flag if audience is
   undefined.
3. **PROVEN** — a short table: element | business-model or mechanic |
   evidence (with cited numbers/sources) | proven-for-this-audience?
   (🟢/🟡/🔴). Then the **#1 "wrong reason" failure risk**.
4. **BETTER** — bullet list, each with the statistical-superiority claim
   and a ✅/❌ on the 10/10 consensus gate (reclassify failures as New).
5. **NEW** — the primary bet, its fastest cheapest signal test, what
   "heat" would look like if it's working, and 2–4 backup bets.
6. **Kill-for-the-wrong-reason checklist** — the 3–5 Proven/Better things
   that MUST be nailed before the New bet is even worth showing the market.
7. **Verdict + next move** — proceed / reframe / kill, and the one thing to
   do next (usually: lock the audience, or run the cheapest signal test on
   New).

Keep it sharp. The value is in the evidence behind "Proven," the honesty of
the consensus gate, and the backup New bets — don't bury those under
restated definitions.
